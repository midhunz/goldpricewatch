## T0.4 — Redirect / canonicalisation matrix

| Request | First status | Hops | Final URL |
|---|---|---|---|
| `http://goldpricewatch.com` | **308** | 1 | `https://goldpricewatch.com/` |
| `http://www.goldpricewatch.com` | **308** | **2** (chain) | `https://goldpricewatch.com/` |
| `https://www.goldpricewatch.com` | **301** | 1 | `https://goldpricewatch.com/` |
| `https://goldpricewatch.com/` | 200 | 0 | — |
| `https://goldpricewatch.com` | 200 | 0 | — |
| `https://goldpricewatch.com/india-gold-prices/` | **308** | 1 | `/india-gold-prices` (no slash) |
| `https://goldpricewatch.com/india-gold-prices` | 200 | 0 | — |
| `https://goldpricewatch.com/does-not-exist` | **404** | 0 | Hard 404, no soft-404 |

**Verdict**

- Hard 404 behaves correctly.
- Canonical host is apex, non-www; trailing slash is **stripped** (site enforces no-slash).
- **One redirect chain:** `http://www` → `https://www` → `https://apex` = 2 hops.
  Fix in `Caddyfile`: redirect `http://www` straight to `https://apex` in a single hop.
- Redirects are **308**, not 301. Google treats 308 as equivalent to 301, so this is not a
  ranking problem, but the audit's "every redirect must be a single-hop 301" acceptance
  criterion is met only in spirit. Worth knowing before someone "fixes" it.
- **T2.4 is confirmed and is worse than a cosmetic mismatch:** the site strips trailing
  slashes, but internal nav/footer links point at `https://goldpricewatch.com/` **with**
  the slash. Homepage `/` happens to 200 either way, so the sitewide damage is limited to
  the homepage link form — but any internal link to a *subpage* carrying a trailing slash
  fires a 308. Audit and normalise link emission at the component level.

### The `FAQPage` markup that does exist is a guideline violation

The three pages carrying `FAQPage` are **exactly the three pages whose FAQ answers do not
render in the HTML** (T0.7 below). Google's FAQPage guidelines require the question and
answer text to be visible to the user on the page. Here the answer text exists **only**
inside `<script>` blocks — the JSON-LD itself and the React flight payload.

Meanwhile `/india-gold-prices`, the one page that *does* render its FAQ answers as visible
text, carries **no `FAQPage` schema at all.**

It is exactly backwards on both counts. Sequencing per the audit is right: fix T3.4 first,
then emit `FAQPage`. Until then this markup is a liability, not an asset — it is the kind
of thing that attracts a structured-data manual action.

**Rich Results Test:** not run — needs an authenticated Search Console / API session.
`NEEDS-OWNER-INPUT`. The parse-level verdict above stands on its own.

## T0.7 — Why FAQ answers don't render — root cause

**Root cause: (a) JS-injected — specifically a client accordion that conditionally *mounts*
its answer panel.** Not a collapsed accordion that ships hidden text, and not missing data.

Evidence, per page, testing each answer string from the page's own JSON-LD against two
slices of the document:

| Page | Answers in DOM markup (scripts stripped) | Answers inside `<script>` payload |
|---|---|---|
| `/dubai-gold-prices` | **0 of 3** | 3 of 3 |
| `/abu-dhabi-gold-prices` | **0 of 3** | 3 of 3 |
| `/chennai-gold-prices` | **0 of 5** | 5 of 5 |

Supporting signals:

- `aria-expanded` appears **25x** on `/dubai-gold-prices` and **41x** on
  `/chennai-gold-prices` — an accordion component is present and is a client component.
- Zero `<details>`/`<summary>` elements — not native disclosure.
- The answer text **is** in the React flight payload, so the data reaches the browser and
  renders after hydration plus a user click. It is simply never in the server HTML.

**Conclusion:** the answer is rendered as `{isOpen && <p>{answer}</p>}` (or equivalent)
inside a `"use client"` accordion. `/india-gold-prices` uses a different component that
renders answers unconditionally.

**Fix (feeds T3.4):** always render the answer element; collapse it with CSS
(`max-height` / `hidden` / `grid-template-rows`), never by conditional mount. Then make the
`/india-gold-prices` component the single shared one, and only then emit `FAQPage`.
